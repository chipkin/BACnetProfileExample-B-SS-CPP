## [1.4.0] - 2026-10-27

Built on CAS BACnet Stack 6.x (`69b6249f`).

### Added

- **`--deviceName <text>`** sets the Device's Object_Name at start-up, like
  `--deviceID` sets its instance (ASHRAE 135-2024 cl. 12.1.1.3, 12.1.1.4).
  Object_Name must be unique on the internetwork, so two units could not share
  the compile-time name. The default is unchanged (`Chipkin Example B-SS`). A name
  must be 1..255 bytes with no control characters, otherwise the example warns and
  keeps the default. The name is not writable over the network. Documented in the
  README, PICS and TUTORIAL.
- **Wire Test** `tests/configuration_test.py` checks `--deviceID` and `--deviceName`
  over Who-Is, ReadProperty and Who-Has.

### Changed

- **Wire Tests default to this example's own port, 47820.** Runs that pass `--port`
  are unchanged.
- **Updated to CAS BACnet Stack 6.x `69b6249f`.** No code change was needed.
- **Comments in `main.cpp` and `TUTORIAL.md` follow the current stack:** an object the
  application does not name reads back as `"Object <type>,<instance>"`, not
  `"undefined"`, and a BACnet/IP Network Port's `APDU_Length` is generated by the
  stack, not refused.
- **PICS** now cites the CAS BACnet Stack's property profiles for the
  objects-and-properties tables.

### Fixed

- **Requests no longer go unanswered on Windows** (vendored `common/` 3.4.1). A
  request that arrived just as the 10 ms receive timeout expired was discarded.
  The example now waits with `select()` and receives only when data is ready.
- **`--help` no longer lists options the example ignored.** `--dcc-password` is gone
  (a B-SS has no DeviceCommunicationControl) and `--xml` now works, printing each
  frame as XML.
- **PICS: Database_Revision is 5**, not 0. The stack adds one per object created at
  start-up (cl. 12.11): the Device and its four objects.

## [1.3.0] - 2026-10-16

The sensor now performs the B-SS Profile Function (ANSI/ASHRAE 135-2024 Annex L.4.5,
"Ability to provide values for any of its BACnet objects upon request") with live
readings and a failure mode. The BACnet surface is unchanged (DS-RP-B, DM-DDB-B,
DM-DOB-B; the same five objects).

Built on CAS BACnet Stack 6.x (`64b2cfac`, 6.0.23).

### Added

- **Sensor simulation.** Once a second Analog Input 1 moves 0.5 C between 18.0 and
  26.0, Binary Input 1 toggles every 3 s and Multi-State Input 1 steps 1, 2, 3
  every 4 s. The up/down keys nudge Analog Input 1.
- **Analog Input 1 `Reliability`** reads `no-fault-detected`, or `open-loop` while
  a simulated sensor wire is broken, and the FAULT bit of `Status_Flags` follows
  (cl. 12.2.7, 12.2.9). The TUTORIAL explains how to report a sensor fault from
  real hardware.
- **Wire Tests** under `tests/` run with `tests/run_wire_tests.py`: discovery
  (Who-Is, `Object_List`, every `Property_List` entry read), sensing, and failure
  modes (Error responses per cl. 15.5.1.3.1, WriteProperty rejected per cl. 18.9).
- **TUTORIAL.md** and **docs/PICS.md** (a Protocol Implementation Conformance
  Statement in the Annex A shape). The README is shorter and links to prebuilt
  binaries.

### Changed

- **Protocol_Revision 24 to 30.**
- **Segmentation is now supported** (`segmented-both`, `Max_Segments_Accepted` 16,
  `APDU_Segment_Timeout` 5000 ms).
- **The Device is named "Chipkin Example B-SS"** (was "Rainbow") so examples on the
  same network can be told apart.
- **The build is `cmake -B build -S .` on every platform.** The stack's sources are
  compiled into the executable; no separate library is built first.
- The Device object is now included in the PICS object tables.

### Fixed

- **Network Port 1 properties a client could not read.** `IP_DNS_Server`,
  `FD_BBMD_Address` and `FD_Subscription_Lifetime` returned an Abort or Error when
  a client such as BACnet Explorer read every property in `Property_List`; they now
  return values. Fixed by the stack update.
- **`Application_Software_Version` and `Firmware_Revision` were stale.** The first
  now follows the example's version, the second is built from the running stack's
  version.
- **PICS generation** no longer drops the `Property_List` row.

## [1.2.0] - 2026-09-15

Built on CAS BACnet Stack 6.x (`abd4cee1`, 6.0.21).

### Changed

- **Updated to the current CAS BACnet Stack interface.** `GetProperty*` callbacks
  take a trailing `errorCode`, so `State_Text` with an out-of-range index now
  answers Error `invalid-array-index`. `BACnetStack_AddNetworkPortObjectWithNetworkNumber()`
  is merged into `BACnetStack_AddNetworkPortObject()`. Links are identified by
  Network Port instance. `GetSystemTime` returns `CASBACnetTime`.
- **`common/` 2.0.0** (breaking; see `common/CHANGELOG.md`). Re-copy it if you
  reuse it in your own project.
- **Links the stack through the `CASBACnetStack::Adapter` CMake target.** The
  `CAS_BACNET_STACK_LINK` option selects the link mode; call `LoadBACnetFunctions()`
  once at the top of `main()`.
- **Release binaries** are published with size and start-up metrics.
- README gained generated objects-and-properties and footprint sections, and the
  stale version references were corrected.

### Fixed

- **`APP_VERSION`** now matches the release tag.
- Documentation corrections: version banner and sample output, troubleshooting
  entries, and parallel-build guidance for the first compile.

## [1.0.2] - 2026-06-16

### Fixed

- **Windows subnet-mask parsing.** A mask string that failed to parse could be
  read uninitialized; it now falls back to the limited broadcast.

## [1.0.1] - 2026-06-16

### Added

- `State_Text` ("On", "Off", "Auto") on Multi-State Input 1.
- README footprint section and a note that the CAS BACnet Stack is a licensed
  product. Source comments on changing the Vendor Identifier and feeding live
  sensor readings into the callbacks.

### Changed

- Build warnings (`-Wall -Wextra` / `/W4`) on the example's own sources.

### Fixed

- Required object properties are no longer enabled by hand; the stack enables
  them. Only optional properties need `SetPropertyEnabled`.
- Uses `inet_pton` instead of the deprecated `inet_addr` (MSVC C4996).

## [1.0.0] - 2026-06-16

### Added

- Initial **B-SS (BACnet Smart Sensor)** profile example for the CAS BACnet Stack
  in C++.
- **Device** object (default instance `389001`, vendor `389`) and read-only
  **Analog Input 1**, **Binary Input 1**, **Multi-State Input 1** and
  **Network Port 1** with full BACnet/IP addressing.
- **DS-RP-B** (ReadProperty) and Who-Is / I-Am discovery; an I-Am is broadcast at
  start-up.
- All required properties for Protocol_Revision 24.
- Command-line options `--port <n>` and `--deviceID <n>`; interactive keys `h`,
  `q` and up/down (nudge Analog Input 1).
- Cross-platform CMake build, with the CAS BACnet Stack as a git submodule
  (clone with `--recursive`) and Windows and Linux release binaries.
